# Распознавание РЖЯ

Веб-приложение, которое распознаёт жесты русского жестового языка с камеры
планшета или телефона. Всё считается прямо на устройстве, на его видеокарте
(WebGPU). Сервер не нужен. После первого открытия приложение работает без
интернета.

## Как пользоваться

1. Открыть адрес приложения в Safari (iPhone, iPad) или Chrome (Android).
2. Разрешить доступ к камере.
3. Добавить на экран «Домой»: в Safari «Поделиться» → «На экран Домой».
   Приложение откроется во весь экран, как обычное.
4. Нажать «Начать» и показывать жесты. Двойной тап по экрану останавливает.

При первом запуске скачивается около 65 МБ, лучше по Wi-Fi.

Нужен браузер с WebGPU: iOS / iPadOS 18 и новее, Chrome 121+ на Android.

| Устройство | Одно распознавание |
|---|---|
| iPad Air (M4) | ≈ 0,18 с |
| iPhone 13 | ≈ 0,58 с (распознаёт реже, приложение подстраивается само) |

## Как устроено

- `recognizer.js` работает так:
  - берёт 32 кадра (около секунды видео), сжимает каждый в квадрат 224×224 и отдаёт модели;
  - слово выводится, если два окна подряд уверены на 70% и больше, или одно окно уверено на 90% и больше;
  - на медленных устройствах окна реже, поэтому хватает одного окна с уверенностью 70%.
- `cloud.js` — распознавание на сервере с видеокартой (модель SignFlow-R). Адрес сервера
  берётся из `server.json`. Планшет находит человека, вырезает кадр и отправляет 15 кадров
  в секунду (около 0,6 Мбит/с), сервер отвечает словами. Если сервер недоступен, приложение
  само переходит на модель в устройстве (S3D) и возвращается к серверу, когда он появится.
  `?server=0` — работать только на устройстве.
- `framer.js` + `pose-worker.js` находят человека (MediaPipe Pose, на процессоре, в фоновом
  потоке) и вырезают кадр так, как модель распознаёт лучше всего: ширина 2,4 ширины плеч,
  высота 2,9, верх на 1,6 выше плеч. Если человек стоит неудачно, на экране подсказка:
  «Отойдите чуть дальше», «Подойдите ближе», «Встаньте по центру», «Встаньте перед камерой».
  `?debug` показывает в углу, что именно видит модель, и её три лучших варианта.
- `app.js`: интерфейс по макету из Figma (393×852, телефон): заставка, чат, экраны
  жестов, голоса, клавиатуры и истории. Два цвета (`#EEEDDE` и `#821414`), шрифт Golos Text,
  все переходы на пружинах (`spring.js`). `capture.js` — камера и распознавание без
  интерфейса. `icons.js` собирается из `icons/*.svg` скриптом `tools/build_icons.py`.
  **Пока только внешний вид, без логики** (в коде помечено `TODO`): распознавание речи,
  озвучка, сохранение набранного с клавиатуры, история чатов.
  Параметры для проверки: `?sim` — безопасные зоны как в макете (59 и 34),
  `?nosplash` — без заставки, `?screen=gesture|voice|keys|history` — сразу открыть экран,
  `?debug` — что видит модель.
- `sw.js` держит все файлы в кэше устройства для работы без сети.
- `model/s3d.onnx` — модель S3D из easy_sign, пересобранная из 2D-операций
  (в браузере нет 3D-свёрток) и сохранённая в половинной точности. Ответы
  совпадают с оригиналом. Скрипт пересборки — `to_2d.py` в исходном проекте.

## Приложения для iPhone

Их два. Оба собираются на GitHub в файл `.ipa` без подписи и ставятся на iPhone с Windows
через Sideloadly, без Mac и без App Store. Пошагово — [docs/ios-install.md](docs/ios-install.md).

### На Swift (`swift/`, файл `RSL-swift.ipa`) — основное

Отдельное приложение, без встроенного браузера. Веб-версия остаётся образцом того, как всё
должно выглядеть и работать; здесь то же самое сделано средствами iOS.

- `swift/RSL/Engine/` — камера (AVFoundation), распознавание и поиск человека, без интерфейса:
  - `Recognizer.swift` — модель S3D через ONNX Runtime. Сначала считает на процессоре, в фоне
    пробует Core ML и переходит на него, только если ответ тот же, а считает он быстрее.
    Кольцо из 32 кадров и правило принятия слова — те же, что в `recognizer.js`.
  - `Framer.swift` — находит плечи и нос детектором позы iOS (Vision) и вырезает кадр по той же
    мерке, что `framer.js`: 2,4 × 2,9 ширины плеч. Подсказки, как встать, те же.
  - `Cloud.swift` — сервер SignFlow-R по протоколу `cloud.js`; `server.json` сначала
    спрашивается у сайта.
  - `Capture.swift` — связывает их: сервер, пока он отвечает, иначе модель в телефоне.
- `swift/RSL/UI/` — экраны по макету на SwiftUI: заставка, чат, жесты, голос, клавиатура,
  история. Заглушки те же, что в веб-версии, и так же помечены `TODO`.
- Иконки, шрифт, словарь и `server.json` не продублированы: `swift/tools/prepare.py` берёт
  их из файлов веб-версии при сборке, иконки рисуются из тех же путей SVG. Проект Xcode
  пишет XcodeGen по `swift/project.yml`.
- `swift/RSL/Resources/s3d.onnx` — та же модель S3D из 2D-операций, в полной точности
  (в браузере она в половинной).
- `swift/RSLTests/` — тесты, которые идут в симуляторе при каждой сборке: модель в приложении
  отвечает так же, как на компьютере (`tools/reference.py`), кадры превращаются в нужные
  числа, расчёт кадрирования и правило принятия слова совпадают с веб-версией.
- `.github/workflows/ios-swift.yml` — тесты, снимки экранов из симулятора и `.ipa`.
- Трижды нажать на название чата — табличка с тем, что видит модель и как быстро считает.

### Веб-версия в оболочке (`ios/`, файл `RSL.ipa`) — запасное

То же веб-приложение, упакованное в оболочку Capacitor.

- `ios/` — проект Xcode, `capacitor.config.json` — его настройки, `package.json` —
  версии Capacitor.
- `scripts/www.mjs` копирует в `www/` только то, что нужно страницам; оттуда файлы попадают
  внутрь приложения. С сайта ничего не подгружается.
- `platform.js` — три отличия оболочки от браузера: нет service worker, модули `.mjs`
  лежат как `.js`, `server.json` сначала спрашивается у сайта.
- `.github/workflows/ios.yml` собирает `.ipa` без подписи на Mac в GitHub Actions: по кнопке
  **Run workflow** или при отправке в ветку `ios`. На изменения в `main` сборка не запускается.
